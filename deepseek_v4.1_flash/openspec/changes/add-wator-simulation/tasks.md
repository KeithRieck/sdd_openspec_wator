## 2. Simulation core

- [ ] 2.1 Create `src/simulation/WatorSimulation.js` with the flat grid array of entity IDs plus an `empty` marker, an ID-keyed map of entities, a monotonic `nextId`, chronon counter, and history array. Verify: construction sizes the array from the config constants and the module imports nothing from Phaser (`app-shell/static-hosting` §4.1).
- [ ] 2.2 Implement the private `_place(entity, index)` / `_clear(index)` pair and route `move`, `spawn`, and `remove` through them so no other method writes the grid. Verify: a search shows the grid array is written only inside these two methods, satisfying `world-model` §3.2 and §3.3.
- [ ] 2.3 Implement toroidal neighbor addressing returning only north, east, south, and west, with edge wrapping. Verify: querying a corner cell returns the opposite-edge cells and never returns a diagonal (`world-model` §1.2, §1.3).
- [ ] 2.4 Implement random world seeding using the configured densities and the single RNG. Verify: a freshly seeded world has roughly the configured proportions, contains no double-occupied cells, and never calls `Math.random()` directly (`world-model` §2.1-§2.3).
- [ ] 2.5 Create `src/simulation/Fish.js` extending `Entity`, implementing `act(world)` per `chronon-rules` §2: move to a random adjacent empty cell when one exists; when breeding-ready and moved, leave a newborn in the vacated cell and reset the parent breed timer to `0`; when breeding-ready and unable to move, reset the timer; when not breeding-ready and unable to move, keep aging. Verify: each of the five `chronon-rules` §2 scenarios is observable by stepping a small hand-built world.
- [ ] 2.6 Create `src/simulation/Shark.js` extending `Entity`, implementing `act(world)` in the exact order from design D6: decrement energy first and die immediately at zero; else eat a random adjacent fish (adding `sharkEnergyGain`); else move to a random adjacent empty cell; then apply the breeding branch where eating counts as a successful move. Verify: `chronon-rules` §3, §4, and §5 scenarios are observable, including that a shark at zero energy neither moves nor eats and that a newborn shark starts at `initialSharkEnergy`.
- [ ] 2.7 Implement `WatorSimulation.step()` as the chronon skeleton: advance breed ages, snapshot IDs, shuffle with the single RNG, and let each still-living entity `act(world)` at most once. Verify: a newborn never acts during its birth chronon and an entity killed mid-chronon is skipped when its turn arrives (`chronon-rules` §1.1-§1.5).
- [ ] 2.8 Implement population sampling: one sample per chronon holding fish and shark counts, capped to the most recent `500` samples. Verify: after more than 500 steps the history length stays at 500 and retains the newest samples (`population-history` §1.1-§1.3).
- [ ] 2.9 Implement extinction detection and terminal status. Verify: driving sharks to zero yields `Sharks extinct`, fish to zero yields `Fish extinct`, both in one chronon yields `Ecosystem collapsed`, and each auto-pauses (`population-history` §2.1-§2.4).
